# Technical Coding Interview Scorecard

This rubric assesses a candidate's ability to translate logic into working, maintainable code. It covers problem comprehension, data structures, algorithms, code cleanliness, and testing.

## Scoring Rubric

* **5 - Strong Hire:**
  * **Traits:** Flawless or near-flawless execution. Optimal solution reached quickly. Highly communicative.
  * **Evidence:** Writes production-ready, clean, modular code. Immediately identifies edge cases and proactively writes tests. Discusses time/space complexity accurately without being prompted.
* **4 - Hire:**
  * **Traits:** Solid problem-solving. Reaches optimal or near-optimal solution with minor hints.
  * **Evidence:** Writes readable, working code. Catches most edge cases. Can explain complexity. May have minor bugs but fixes them quickly when pointed out or through their own dry-run.
* **3 - Neutral:**
  * **Traits:** Reaches a sub-optimal solution (e.g., brute force) and struggles to optimize. Needs significant hints.
  * **Evidence:** Code is messy but works eventually. Misses several edge cases. Needs help to identify bugs. Complexity analysis is shaky.
* **2 - Lean No Hire:**
  * **Traits:** Fails to complete the problem even with substantial help. Logic is severely flawed.
  * **Evidence:** Writes pseudocode instead of actual code. Does not understand basic data structures (e.g., uses an array instead of a hash map for O(1) lookups). Cannot trace through their own code.
* **1 - Strong No Hire:**
  * **Traits:** Cannot write basic syntax. Shows complete lack of programming fundamentals.
  * **Evidence:** Completely stuck. Does not communicate. Refuses hints or argues with the interviewer about basic computer science facts.

## Hiring Manager Notes

For the Hiring Committee:
- Differentiate between "stuck on a trick" and "lacks fundamental skills". A candidate who misses a clever math trick but writes clean, tested, brute-force code might still be a "Hire" depending on the role.
- A "Strong Hire" indicates the candidate can hit the ground running and write code that others can learn from.
- A "Neutral" is typically a No Hire for senior roles, but might be acceptable for a junior role if they demonstrated high coachability.
