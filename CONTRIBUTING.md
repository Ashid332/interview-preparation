# Contributing to the Engineering Interview Handbook

First off, thank you for considering contributing to the Engineering Interview Handbook! It's people like you that make this an incredible resource for the engineering community.

## 🎯 Our Philosophy

This is **not** a dump of interview questions. Every page should be a high-quality educational resource that prepares someone for an interview. 

When contributing, remember:
1. **Teach, don't just list.** Explain the "why" and "how".
2. **Quality over quantity.** One excellent explanation is better than ten shallow ones.
3. **Include the Hiring Manager Perspective.** We want candidates to understand what interviewers are actually looking for.

## 🛠️ How to Contribute

### 1. Reporting Bugs & Typos
Found a typo, a broken link, or outdated information? 
- Please open a [Bug Report](.github/ISSUE_TEMPLATE/bug-report.yml).
- Or, simply fork the repository, make the fix, and submit a Pull Request!

### 2. Suggesting New Content
Have an idea for a new topic, learning path, or cheat sheet?
- Open a [Content Request](.github/ISSUE_TEMPLATE/content-request.yml) to discuss it before writing. This ensures your hard work aligns with the repository's goals.

### 3. Submitting Interview Experiences
Just finished an interview loop? We'd love to hear about it!
- Use the [Interview Experience Submission](.github/ISSUE_TEMPLATE/interview-experience.yml) template.
- Your experience will be anonymized (if requested) and added to the relevant Company Guide.

## 💻 Pull Request Process

1. **Fork the repo** and create your branch from `main`.
2. **Use the provided Markdown templates** if you are adding a new topic or behavioral question. 
3. **Keep it professional.** No emojis (except for structural icons), no motivational fluff. Write like a Senior Engineering Manager.
4. **Format correctly.** Ensure all Markdown is standard, code blocks have language tags, and Mermaid diagrams render correctly.
5. **Issue that PR!** Use the Pull Request template provided.

## 🎨 Writing Style Guide

- **Voice:** Senior engineering manager briefing a promising candidate.
- **Tone:** Direct, practical, encouraging but realistic.
- **Visuals:** Use Mermaid diagrams or tables for complex explanations. Prefer visual data over long paragraphs.
- **AI Practice:** If adding a major topic, end the page with AI Coach prompts (ChatGPT/Claude/Gemini).

## 🤝 Code of Conduct

By participating in this project, you agree to abide by our [Code of Conduct](CODE_OF_CONDUCT.md).

Thank you for helping engineers worldwide achieve their career goals!
