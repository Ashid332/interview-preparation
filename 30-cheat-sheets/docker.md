# Docker Cheat Sheet

## Key Concepts
| Concept | Description |
|---|---|
| Container | A lightweight, standalone, executable package of software that includes everything needed to run an application. |
| Image | A read-only template with instructions for creating a Docker container. |
| Dockerfile | A text document containing all the commands a user could call on the command line to assemble an image. |
| Volumes | Mechanisms for persisting data generated by and used by Docker containers. |

## Must-Know Items
- Difference between VMs and Containers.
- Layered file systems (caching in Docker builds).
- Multi-stage builds to reduce image size.
- Docker Compose for multi-container applications.

## Critical Commands/Patterns
```dockerfile
# Multi-stage build pattern
FROM node:18 AS builder
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
RUN npm run build

FROM nginx:alpine
COPY --from=builder /app/build /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

## Decision Framework
- **CMD vs ENTRYPOINT:** Use `ENTRYPOINT` for the main executable the container should run. Use `CMD` for default arguments to that executable, which can be easily overridden by the user.
- **Alpine vs Debian bases:** Use Alpine for minimal attack surface and small sizes, but be aware of musl libc compatibility issues for some C/C++ compiled binaries.

## Common Mistakes
- Running containers as the `root` user (security risk).
- Including secrets/passwords in the Dockerfile (use environment variables or secret managers).
- Not using `.dockerignore`, resulting in large context uploads and leaked local files.
- Creating too many layers by not chaining `RUN` commands (e.g., `RUN apt-get update && apt-get install -y ...`).

## One-Minute Review
- Docker packages apps into portable containers. Master writing efficient Dockerfiles (caching, multi-stage), basic CLI commands, and Compose for local dev.
