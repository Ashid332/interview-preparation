# Problem Solving Framework

## Overview
A structured problem-solving framework is essential for navigating technical interviews successfully. It ensures you don't get stuck, communicate effectively, and cover all bases before writing code. A common framework is: Understand, Plan, Execute, and Review (UPER) or similar variations.

## Interview Questions
* **Companies:** All.

### Excellent Answer
"Before I write any code, let me make sure I understand the requirements. Can the input array be empty? Are there negative numbers? Okay, my plan is to use a Hash Map to track occurrences, which gives us O(N) time. Let's trace through an example to verify the logic."

### Common Mistakes
* Starting to code immediately after hearing the prompt.
* Not speaking out loud (silent candidates are hard to evaluate).
* Getting defensive when given a hint by the interviewer.
* Failing to test the code with edge cases after writing it.

## Real-World Applications
* Debugging complex production issues.
* Breaking down large feature requests into manageable engineering tasks.
* Collaborating with cross-functional teams to define product requirements.

## Practice Problems

| Problem | Topic | Difficulty | Focus |
| :--- | :--- | :--- | :--- |
| Any LeetCode | Framework | Varies | Apply UPER steps |
| System Design | Framework | Hard | Clarifying requirements |
| Bug Fixing | Debugging | Medium | Root cause analysis |

## Hiring Manager Perspective
"I care more about the framework than the final answer. If a candidate systematically breaks down the problem, communicates their assumptions, and handles edge cases, I'll hire them even if there's a minor bug in the final code."
